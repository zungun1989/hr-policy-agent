# AI Tooling Documentation

## Overview

This project was built with significant assistance from **Claude Code** (Anthropic's CLI AI agent) using the `claude-sonnet-4-6` model. Approximately 90% of the code was generated or heavily guided by Claude Code, with human review, direction, and integration decisions throughout.

## Tools Used

### Claude Code (Primary)
- **Version**: claude-sonnet-4-6 via Claude Code CLI
- **Usage**: Architecture planning, code generation for all components (RAG pipeline, MCP server, agent orchestrator, FastAPI app, tests, CI/CD, documentation)
- **How used**:
  - Provided the project requirements document (PDF) and asked for a plan
  - Iterated on the plan (deployment platform change from Render to HF Spaces)
  - Claude Code generated each file, handling imports, error handling, and type safety
  - Corpus documents (10 policy files) were generated by Claude Code with human review for realism
  - Mock data (employees, PTO balances, benefits) generated by Claude Code
  - Evaluation questions and gold answers drafted by Claude Code, reviewed for correctness

### Claude API (Runtime)
- **Model**: `claude-haiku-4-5-20251001`
- **Usage**: Agent reasoning, tool selection, response synthesis at runtime
- **Why Haiku**: Cost-effective for iterative agentic loops; typically 3–6 tool calls per conversation

## What Worked Well

1. **Architecture planning**: Claude Code produced a detailed, rubric-aligned plan before writing any code. The plan included all required components and correctly identified the gap between a naive architecture and rubric 5 requirements (fixed seeds, escalation metrics, action safety, graceful failure handling).

2. **Policy document generation**: Claude Code generated 10 realistic company policy documents (2–4 pages each) that are internally consistent and cross-reference each other correctly (e.g., Expense Policy references Remote Work Policy for home office stipend eligibility).

3. **MCP server structure**: The MCP tool definitions, including JSON Schema input schemas and the `requester_confirmed` confirmation gate pattern, were generated correctly on the first attempt.

4. **FastAPI + async MCP integration**: The orchestrator correctly uses `asyncio.run()` to bridge FastAPI's async context with the MCP stdio client.

5. **Test coverage**: Claude Code generated tests for all key requirements including action safety (confirming that `create_mock_hr_ticket` with `requester_confirmed=False` does not create a ticket).

---

## What Was Challenging

1. **MCP SDK version compatibility**: The `mcp` Python SDK changed its API between v1.0 and v1.2. Claude Code initially generated code for an older API (`@app.list_tools()` decorator format). Required a correction to match the v1.2 SDK.

2. **fastembed vs sentence-transformers**: The initial plan used `sentence-transformers`, but this brings PyTorch (~1GB) as a dependency. We switched to `fastembed` for HF Spaces free-tier compatibility. Claude Code adapted the embedding integration correctly after this direction was provided.

3. **HF Spaces Docker port**: HF Spaces Docker SDK requires port 7860 specifically. Claude Code initially suggested port 8000. Required a one-line correction.

4. **Evaluation grading nuance**: The automatic groundedness and citation accuracy metrics are approximations (keyword matching, not semantic similarity). Claude Code generated these metrics as instructed but flagged that human review of at least a sample of responses would be more reliable.
